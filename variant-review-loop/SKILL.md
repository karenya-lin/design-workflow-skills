# Variant review / 設計方案評審

Read [optional profile](../optional-skill-profile/SKILL.md) first; missing helper means
session-only settings, not a block on design discussion. Reuse project-approved tokens.

Assign permanent IDs before showing variants. Never renumber or reuse retired IDs;
use suffixes for revisions. Agree on how many materially different directions to
show; changing only color is not a different layout exploration. Show ID, thumbnail,
rationale, status and trade-offs together so a short user reply maps to one artifact.

Record approved, candidate and retired states with reasons. A request to transfer
one property transfers only that property. Ambiguous ID or conflicting decisions:
ask before editing. Preserve the difference between a reviewer suggestion and the
user's decision; persona votes are not evidence of usability or authorization.

At each round report remaining candidates and the next convergence decision. Keep
rejected artifacts in a user-approved archive when requested; do not delete or move
unrelated files. Apply the selected direction only after approval. Return artifacts,
decision history and unresolved questions. Do not publish client examples.

繁中：永久編號、不重排；方案並列附理由；使用者確認後才落實。
首次設定可略過，之後執行前顯示；淘汰理由保留，封存與刪除不混為一談。
